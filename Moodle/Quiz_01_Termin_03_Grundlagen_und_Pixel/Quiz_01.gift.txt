::Q1_1_2D_FDM_Stabilitaetsgrenze::[markdown]Sie simulieren die instationäre zweidimensionale Wärmeleitung in einer quadratischen Aluminium-Kühlplatte mittels der expliziten Finite-Differenzen-Methode (FDM, 5-Punkt-Laplace-Stern auf einem äquidistanten quadratischen Pixelgitter).

Gegeben sind folgende physikalische und geometrische Parameter\:
* Temperaturleitfähigkeit des Werkstoffs\: $\alpha \= 1{,}25 \cdot 10^{-4}\,\mathrm\{m^2/s\}$
* Räumliche Gitterweite in beiden Koordinatenrichtungen\: $\Delta x \= \Delta y \= 2{,}0\,\mathrm\{mm\}$

Berechnen Sie die **theoretische maximale Zeitschrittweite $\Delta t_{\max}$ in Millisekunden [ms]**, bis zu welcher das explizite zweidimensionale Zeitintegrationsverfahren nach dem Von-Neumann-Stabilitätskriterium numerisch stabil bleibt. *(Geben Sie das Ergebnis als Dezimalzahl in Millisekunden ohne Einheit ein)*
{#8.0:0.1#Richtig! Für die 2D-Wärmeleitung mit explizitem 5-Punkt-Stern lautet die Stabilitätsbedingung s = alpha * dt / dx^2 <= 0.25. Daraus folgt dt_max = dx^2 / (4 * alpha) = (2.0e-3 m)^2 / (4 * 1.25e-4 m^2/s) = 4.0e-6 / 5.0e-4 s = 0.008 s = 8.0 ms.}


::Q1_2_Expliziter_Euler_Abkuehlung::[markdown]Ein aufgeheizter Temperatursensor kühlt in einem ruhenden Ölbad ab. Die zeitliche Änderung seiner Temperatur $T(t)$ (in $^\circ\mathrm\{C\}$) folgt dem linearen Differentialgleichungsmodell erster Ordnung\:
$$\frac\{\mathrm\{d\}T\}\{\mathrm\{d\}t\} \= -k \cdot (T(t) - T_{\text\{Umg\}})$$

Gegeben sind folgende Prozessparameter\:
* Umgebungstemperatur des Ölbads\: $T_{\text\{Umg\}} \= 20{,}0\,^\circ\mathrm\{C\}$
* Abkühlkonstante\: $k \= 0{,}5\,\mathrm\{s\}^{-1}$
* Anfangstemperatur zum Zeitpunkt $t_0 \= 0\,\mathrm\{s\}$\: $T_0 \= 100{,}0\,^\circ\mathrm\{C\}$
* Konstante numerische Zeitschrittweite\: $\Delta t \= 0{,}4\,\mathrm\{s\}$

Berechnen Sie mit dem **expliziten Euler-Verfahren** die numerische Näherung der Sensortemperatur **$T_2$ in $^\circ\mathrm\{C\}$ nach exakt zwei Zeitschritten** (also zum Zeitpunkt $t_2 \= 0{,}8\,\mathrm\{s\}$). *(Geben Sie den Zahlenwert ohne Einheit ein)*
{#71.2:0.2#Richtig! Schritt 1: dT0/dt = -0.5 * (100 - 20) = -40 °C/s -> T1 = 100 + 0.4 * (-40) = 84.0 °C. Schritt 2: dT1/dt = -0.5 * (84 - 20) = -32 °C/s -> T2 = 84.0 + 0.4 * (-32) = 71.2 °C.}


::Q1_3_CodeTracing_FDM_NeumannRand::[markdown]Gegeben sei folgender C\#-Codeausschnitt aus einer 2D-Wärmeleitungssimulation, der einen einzelnen expliziten Zeitschritt für den Gitterknoten $(x\=1, y\=0)$ am oberen Plattenrand berechnet\:

```csharp
double s \= 0.20;
double[,] u \= new double[3, 3]
\{
    \{ 50.0,  60.0,  70.0 \}, // Zeile y = 0 (oberer Rand)
    \{ 50.0, 100.0,  90.0 \}, // Zeile y = 1 (Platteninneres)
    \{ 50.0,  80.0,  80.0 \}  // Zeile y = 2 (unterer Rand)
\};

int x \= 1, y \= 0;
double center \= u[y, x];
double left   \= u[y, x - 1];
double right  \= u[y, x + 1];
double down   \= u[y + 1, x];
double up     \= (y \=\= 0) ? center \: u[y - 1, x]; // Adiabater Neumann-Rand

double uNext \= center + s * (left + right + up + down - 4.0 * center);
```

Welchen exakten numerischen Wert hat die Variable `uNext` nach Ausführung dieses Codeblocks? *(Geben Sie den Zahlenwert ohne Einheit ein)*
{#70.0:0.1#Richtig! Für y=0, x=1 gilt: center = 60.0, left = 50.0, right = 70.0, down = 100.0 und wegen y==0 wird up = center = 60.0 gesetzt. Damit ist uNext = 60.0 + 0.20 * (50 + 70 + 60 + 100 - 240) = 60.0 + 0.20 * 40.0 = 70.0.}


::Q1_4_Stride_Fehlerdiagnose::[markdown]Ein Entwickler möchte ein Graustufen-Temperaturfeld auf einer WPF `WriteableBitmap` (Breite\: $W \= 640\,\mathrm\{px\}$, Höhe\: $H \= 480\,\mathrm\{px\}$, Pixelformat\: `PixelFormats.Bgra32`) darstellen und schreibt folgenden Code\:

```csharp
int width \= 640, height \= 480;
int stride \= width * 3;
byte[] pixelData \= new byte[stride * height];

for (int y \= 0; y < height; y++)
\{
    for (int x \= 0; x < width; x++)
    \{
        int index \= y * stride + x * 4;
        byte val \= GetIntensity(x, y);
        pixelData[index + 0] \= val;
        pixelData[index + 1] \= val;
        pixelData[index + 2] \= val;
        pixelData[index + 3] \= 255;
    \}
\}
bitmap.WritePixels(new Int32Rect(0, 0, width, height), pixelData, stride, 0);
```

Beim Ausführen bricht das Programm mit einer `IndexOutOfRangeException` ab. Was ist die exakte technische Ursache dieses Fehlers? {
=Das Pixelformat Bgra32 belegt 4 Bytes pro Pixel, während stride fehlerhaft mit width * 3 berechnet wurde; dadurch ist das Array zu klein dimensioniert und der Zugriff y * stride + x * 4 überschreitet die Array-Grenze. #Exakt! Bgra32 benötigt 4 Bytes pro Pixel (mindestens 2560 Bytes pro Zeile bei 640 px Breite).
~Das Pixelformat Bgra32 erwartet im Array pixelData zwingend normalisierte float-Gleitkommawerte zwischen 0.0 und 1.0 statt ganzzahliger byte-Werte, wodurch die Typkonvertierung im Speicher fehlschlägt. #Falsch. Bgra32 verwendet 8-Bit-Byte-Kanäle (0 bis 255).
~Die geschachtelte Schleifenreihenfolge (y außen, x innen) verletzt die Column-Major-Speicherarchitektur von WPF-Bitmaps, sodass der Spaltenindex x bereits in der ersten Bildzeile über den Zeilenpuffer hinausläuft. #Falsch. Bitmaps sind in WPF im Row-Major-Format organisiert; y außen und x innen ist optimal.
~Die Methode WritePixels erfordert bei einer Auflösung von 640x480 Pixeln zwingend eine auf Potenzen von zwei aufgerundete Texturbreite (1024 px), da der Grafiktreiber sonst einen Pufferüberlauf auslöst. #Falsch. WriteableBitmap unterstützt beliebige ganzzahlige Bildbreiten ohne Zweierpotenz-Zwang.
}


::Q1_5_CFL_Bilddiagnose_Instabilitaet::[markdown]In einer zweidimensionalen Wärmeleitungssimulation (expliziter 5-Punkt-Stern auf einem äquidistanten Gitter mit $\Delta x \= \Delta y \= 2{,}0\,\mathrm\{mm\}$ und $\alpha \= 1{,}25 \cdot 10^{-4}\,\mathrm\{m^2/s\}$) erhöht ein Ingenieur die Zeitschrittweite $\Delta t$ von $6{,}0\,\mathrm\{ms\}$ auf $12{,}0\,\mathrm\{ms\}$, um die Berechnung zu beschleunigen.

Welches spezifische numerische und optische Phänomen tritt in der animierten Heatmap unmittelbar nach wenigen Zeitschritten auf? {
=Das zentrale Eigengewicht des 5-Punkt-Sterns wird negativ, wodurch benachbarte Gitterknoten in jedem Zeitschritt ihr Vorzeichen alternierend umkehren und als Schachbrettmuster exponentiell gegen +-Unendlich (NaN) divergieren. #Richtig! Bei dt = 12 ms ist s = 0.375 > 0.25, sodass das zentrale Gewicht (1 - 4s) = -0.5 negativ wird und eine hochfrequente Schachbrett-Instabilität auslöst.
~Durch die größere Zeitschrittweite nimmt die numerische künstliche Viskosität stark zu, sodass scharfe Temperaturgradienten übermäßig schnell weichgezeichnet werden, die Lösung aber beschränkt bleibt. #Falsch. Beim Überschreiten der Stabilitätsgrenze wird die Lösung nicht glatter, sondern explodiert oszillatorisch.
~Die explizite Zeitintegration verliert ihre Konsistenz erster Ordnung und friert den letzten gültigen Temperaturzustand dauerhaft ein, weil die Differenzenquotienten zu Null unterlaufen (Underflow). #Falsch. Es tritt ein exponentieller Overflow nach +-Infinity auf, kein Einfrieren.
~Es entsteht ein systematischer Phasenfehler entlang der Hauptdiagonalen des Gitters, durch den sich die Wärmewelle elliptisch statt kreisförmig ausbreitet, ohne dass die Temperaturwerte den Anfangsbereich verlassen. #Falsch. Das Maximumprinzip wird verletzt und die Werte wachsen unbeschränkt an.
}


::Q1_6_Unsafe_Pointer_BGRA_Speicherordnung::[markdown]Für maximale Render-Performance schreibt eine Simulationsschleife über unmanaged C\#-Pointer direkt in den Back-Buffer einer `WriteableBitmap` (`PixelFormats.Bgra32`)\:

```csharp
bitmap.Lock();
unsafe
\{
    byte* pBackBuffer \= (byte*)bitmap.BackBuffer;
    int stride \= bitmap.BackBufferStride;
    for (int y \= 0; y < height; y++)
    \{
        byte* row \= pBackBuffer + (y * stride);
        for (int x \= 0; x < width; x++)
        \{
            byte heat \= GetHeatByte(x, y); // 0 = kalt (0 °C), 255 = heiß (100 °C)
            row[x * 4 + 0] \= heat;
            row[x * 4 + 1] \= 0;
            row[x * 4 + 2] \= (byte)(255 - heat);
            row[x * 4 + 3] \= 255;
        \}
    \}
\}
bitmap.AddDirtyRect(new Int32Rect(0, 0, width, height));
bitmap.Unlock();
```

Der Entwickler wollte heiße Zonen (`heat = 255`) tiefrot und kalte Zonen (`heat = 0`) tiefblau einfärben. Welches Ergebnis zeigt sich tatsächlich auf dem Bildschirm und warum? {
=Die Farbdarstellung ist exakt invertiert (heiße Zonen erscheinen blau, kalte Zonen rot), weil Bgra32 im Speicher an Byte-Offset 0 den Blau-Kanal und erst an Byte-Offset 2 den Rot-Kanal ablegt. #Exakt! In Bgra32 gilt Little-Endian-Reihenfolge: Offset 0 = Blau, Offset 1 = Grün, Offset 2 = Rot, Offset 3 = Alpha.
~Das gesamte Bild bleibt transparent (Hintergrund scheint durch), weil der Alpha-Kanal in Bgra32 an Byte-Offset 0 liegt und für kalte Regionen mit heat = 0 vollständig durchsichtig geschaltet wird. #Falsch. Der Alpha-Kanal liegt an Offset 3 und ist dort fest auf 255 (deckend) gesetzt.
~Die Farben werden wie gewünscht dargestellt (heiß = rot, kalt = blau), weil die Methode AddDirtyRect vor der Übergabe an DirectX eine automatische Big-Endian-Konvertierung von RGB nach BGRA durchführt. #Falsch. AddDirtyRect markiert nur den geänderten Speicherbereich ohne Farbkanäle umzusortieren.
~Jede zweite Bildspalte weist einen Grünstich auf, weil die Zeigerarithmetik byte* row = pBackBuffer + (y * stride) ohne expliziten Cast auf uint* um jeweils ein Byte pro Pixelzeile verrutscht. #Falsch. Da BackBufferStride bereits in Bytes angegeben ist, adressiert byte* + y * stride exakt den Zeilenanfang.
}


::Q1_7_Modelltheorie_und_Digitaler_Zwilling::[markdown]Welche der folgenden Aussagen zur allgemeinen Modelltheorie nach Herbert Stachowiak sowie zur Klassifikation des Digitalen Zwillings nach Michael Grieves und Werner Kritzinger et al. sind **fachlich zutreffend**? *(Wählen Sie alle richtigen Aussagen)* {
~%50%Nach dem Verkürzungsmerkmal von Stachowiak erfasst ein Modell niemals alle Attribute des realen Originals, sondern abstrahiert gezielt auf diejenigen Eigenschaften, die für den jeweiligen Untersuchungszweck relevant sind. #Richtig! Dies ist das zentrale Verkürzungsmerkmal nach Stachowiak.
~%50%Nach Kritzinger et al. unterscheidet sich ein Digitaler Zwilling (Digital Twin) vom Digitalen Schatten (Digital Shadow) dadurch, dass ein automatisierter bidirektionaler Datenfluss zwischen physischem und digitalem Objekt besteht. #Richtig! Erst der automatisierte Rückkanal (z. B. Aktor-Eingriff / Parameter-Update) macht den Digital Shadow zum Digital Twin.
~%-50%Ein hochdetailliertes 3D-CAD-Baugruppenmodell inklusive kinematischer Zwangsbedingungen erfüllt nach Kritzinger et al. bereits ohne automatisierte Sensordaten-Kopplung zur realen Anlage alle Kriterien eines Digital Shadow. #Falsch! Ohne automatisierten Datenfluss vom physischen Objekt zum Modell handelt es sich lediglich um ein Digital Model.
~%-50%Nach dem pragmatischen Merkmal von Stachowiak ist die Gültigkeit eines mathematischen Simulationsmodells eine rein objektive Eigenschaft des Originals und vollkommen unabhängig vom menschlichen Nutzer und dem Einsatzzweck. #Falsch! Das pragmatische Merkmal betont gerade den Bezug auf Subjekt (Für wen?), Zeitintervall (Wann?) und Zweck (Wozu?).
}


::Q1_8_Randbedingungen_und_Doppelpufferung::[markdown]Bei der Implementierung der zweidimensionalen instationären Wärmeleitung auf einem diskreten Pixelgitter müssen thermische Randbedingungen und Speicherstrukturen korrekt gewählt werden. Welche der folgenden Aussagen sind **physikalisch und programmiertechnisch zutreffend**? *(Wählen Sie alle richtigen Aussagen)* {
~%50%Eine ideale thermische Wärmeisolierung am Plattenrand (adiabater Rand ohne Wärmefluss über die Grenze) wird mathematisch durch eine homogene Neumann-Randbedingung (dT/dn = 0) modelliert, indem der Randwert auf den benachbarten Geisterknoten gespiegelt wird. #Richtig! Verschwindende Normalenableitung bedeutet identische Temperatur auf beiden Seiten des Rands (Wärmestrom = 0).
~%50%Ein aktives Heizelement, das einen Teilbereich der Platte dauerhaft auf einer fest vorgegebenen Solltemperatur von 80 °C hält, entspricht einer Dirichlet-Randbedingung (Vorgabe des Funktionswerts selbst) und muss nach jedem Zeitschritt fest eingeprägt werden. #Richtig! Eine Dirichlet-Bedingung gibt den Zustandswert T direkt vor.
~%-50%Wenn beim expliziten 5-Punkt-Stern aus Speicherplatzgründen auf ein zweites Array (uNext) verzichtet und direkt in-place im selben Array überschrieben wird, bleibt das Verfahren ein symmetrisches explizites Verfahren mit identischer Stabilitätsgrenze s <= 0.25. #Falsch! In-place-Überschreiben vermischt alte und neue Zeitschritte asymmetrisch (Gauß-Seidel-Effekt) und verfälscht die isotrope Ausbreitung.
~%-50%Bei einer homogenen Dirichlet-Randbedingung (T_Rand = 0 °C) ist der Wärmestrom über den Plattenrand zu jedem Zeitpunkt exakt gleich Null, sodass die gesamte thermische Energie im Inneren der Platte konstant erhalten bleibt. #Falsch! Ein fester 0-°C-Rand wirkt als Kühlkörper (Wärmesenke), über den kontinuierlich Energie abfließt.
}
